How to regenerate the DDL

dotnet ef dbcontext script `
  -p src\InventoryPOS.Data\InventoryPOS.Data.csproj `
  -s src\InventoryPOS.Data\InventoryPOS.Data.csproj `
  -o database\Migrations\Schema.sql

To add a schema change:

dotnet ef migrations add <Name> `
  -p src\InventoryPOS.Data\InventoryPOS.Data.csproj `
  -s src\InventoryPOS.Data\InventoryPOS.Data.csproj

Migrations are applied automatically on startup by DataService.InitializeAsync.

Conventions

  • Primary keys — every table has an INTEGER autoincrement Id.
  • Audit columns — every table derived from BaseEntity carries CreatedAt, UpdatedAt (ISO-8601 text) and IsDeleted (0/1).
  • Soft delete — nothing is physically deleted by the app. A global query filter excludes IsDeleted = 1 from every BaseEntity query.
  • Tenancy — every business-owned table carries BusinessId. A global query filter restricts rows to the active tenant (ITenantContext.BusinessId), and is bypassed only when no tenant is active (seeding, sign-in) or explicitly via IgnoreQueryFilters().
  • Enums are persisted as INTEGER; money values as TEXT with fixed precision (e.g. (18,2) or (18,4) for cost).
  • Quantities are decimal in the model and REAL in SQLite. The provider cannot aggregate, order, or compare TEXT-backed decimals, so a value converter stores physical units as REAL. This enables fractional/weighed units (0.75 kg) and keeps stock SUM/ORDER BY queries server-side.
  • Timestamps are stored as SQLite TEXT in ISO-8601 form.

Foreign keys and delete behaviour

Most tenant-owned FKs use Cascade or Restrict to protect data integrity:

  • Cascade — child rows belonging to a parent: Branches, Categories, Suppliers, Customers, SubscriptionPayments, SaleItems, PurchaseOrderItems, StockTransferItems, StockMovements, StockAlerts.
  • Restrict — references that must not silently remove history: Sales.BusinessId, Products.BusinessId, Payments.SaleId, StockMovements.ProductId, StockReservations, AuditEntries, StkPaymentIntents.
  • SetNull — optional references: *.BranchId, Sales.CustomerId, Products.SupplierId/CategoryId, Users.BranchId.

Indexes

Highlighted indexes:

  • Unique: Businesses.Email, Products(Barcode, BusinessId), Sales.InvoiceNumber, Sales.ReceiptNumber, StkPaymentIntents.ApiRef.
  • Composite/hot-path: StockMovements(ProductId, CreatedAt), StockMovements(BusinessId, CreatedAt), AuditEntries(BusinessId, Id), AuditEntries(BusinessId, OccurredAt), StockReservations(BusinessId, Status, ExpiresAt), StockReservations(BusinessId, Reference), StkPaymentIntents(BusinessId, Status).

Encryption at rest

Whole-database encryption (SQLCipher) is opt-in and off by default. When enabled, the passphrase is kept in SecureStorage (key DatabasePassphrase) and an existing plaintext database is migrated in place using ATTACH DATABASE … KEY followed by sqlcipher_export. Enabling or disabling requires an application restart. See DatabaseEncryptionService.
